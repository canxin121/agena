# AI Bot：直接管理项目与会话

可以创建多个有名字的 AI Bot，每个 Bot 都有独立的附加系统指令、对话历史和会话模型选择。Bot 面向整台电脑，不属于任何项目，也没有默认工作目录。Web 与 TUI 共用服务端登记的身份；具体项目工作仍在明确选定的普通项目会话中执行。

## 打开 Bot

Web 点击主导航或项目侧栏的 **AI Bot**，也可以直接打开 `/bot` 或输入 `/bot` 命令。无需先选择项目。页面保留完整聊天功能：模型选择、历史、草稿、附件、工具结果和权限审批。

TUI 在启动页选择 **AI Bot**（按 `b`），或使用 `Ctrl+B`、`/bot`。Bot 使用原有会话界面，`Ctrl+G` 返回项目与会话列表。Bot 设置只提供名称和「附加系统指令」；称呼、语气及回复语言都可直接写进这段指令。普通项目会话继续使用工作区的助手设置。

每个 Bot 有稳定 UUID，名字在启用的 Bot 之间不可重复（去除首尾空格并忽略大小写）。升级时通过一次性的本地数据库迁移保留原 Bot 会话，并把曾经独立保存的称呼、语气与语言偏好合并到附加系统指令，随后正式服务只读取当前数据结构。新建 Bot 默认没有附加系统指令（模型按通常方式回复）。重新打开或重启服务保留对话、人工修改的标题及模型选择。普通会话管理删除 Bot 对话后，重新打开只为这个 Bot 建立新对话，保留 UUID 和附加系统指令，不恢复已删除内容。

归档要求 Bot 空闲，不能有运行中、排队中的执行或待处理的原生交互。归档保留历史并撤销管理权限；默认入口选择最早创建且未归档的 Bot。全部归档后显示创建入口，不会自动恢复已归档 Bot。Bot 不能查看或管理其他 Bot 的会话、归档历史及其分支。

附加系统指令与对话彼此独立。Bot 使用实例级记忆和提醒策略，普通项目会话保留各自的项目记忆与策略；切换项目不会改变 Bot 的附加系统指令、无工作目录状态或权限来源。模型选择属于各自的会话；全局作用域不自动批准文件或命令权限。

## 侧边栏管理 Bot

进入 Bot 时，Web 侧边栏和手机抽屉只展示具名 Bot 列表及新建、搜索、编辑、归档操作，不显示项目目录或普通会话的收藏、置顶、最近和运行中分组。切回项目聊天时，项目侧栏恢复，并保留原先的项目位置。

| 操作 | 入口与结果 |
|---|---|
| 查找 | 在独立的 Bot 侧栏按名称或附加系统指令关键词筛选；项目和普通会话在项目视图中管理 |
| 新建 | 点击 Bot 区域的「新建」，填写名称和可选附加系统指令后保存；新 Bot 出现在列表，可直接打开 |
| 打开 | 点击具体 Bot 行，进入它自己的会话，保留其他 Bot 和项目会话的草稿与模型 |
| 改名 | 使用该行的操作菜单，编辑名称；Bot 身份和原有聊天不变 |
| 修改附加系统指令 | 从对应 Bot 的操作菜单打开唯一的多行指令文本框；不影响其他 Bot |
| 会话操作 | 该行「更多」菜单与项目会话行使用同一套菜单：收藏、改名、会话设置、复制/导出记录，以及 Bot 专属的编辑与归档 |
| 移除 | 使用「归档」并明确确认目标 Bot；从启用列表移除，聊天历史保留 |

Bot 行和项目会话行渲染同一套侧边栏组件：共享的行框架、溢出按钮、`SidebarSessionActionMenu`、菜单项构造器与锚定菜单状态机（`useSessionActionMenu`）。Bot 行的菜单直接作用于该行自己的会话，因此无需先切换选中；会话设置跳到该会话的专属设置页，复制与导出复用同一条记录生成流程。

侧边栏与聊天页使用同一套管理弹窗和数据。附加系统指令可以写成长篇角色卡（上限 256 KiB UTF-8，主要用于防止异常数据），**真正的限制是所选模型的上下文长度**：装配提示词超出预算时会返回明确错误，说明指令大约占用多少 token、当前模型允许多少，而不是静默截断。参考即梦、酒馆这类社区人格卡，几 KB 到几十 KB 都很常见。保存后从后续模型回合生效；列表、对应 Bot 的聊天标题和标签页同步更新。版本冲突时保留本地输入，可以明确重新加载最新资料再修改；不会自动覆盖另一端的更新。

归档正在执行、排队或等待人工交互的 Bot 会提示先处理对应工作。归档当前 Bot 后不会偷偷切换到另一个 Bot；全部归档时仍保留明确的新建入口。Bot 列表可以独立滚动和折叠。项目导航只在项目视图显示，不与 Bot 侧栏混在一起。

## 全局操作与目标路径

Bot 会话的项目关联为空，原生接口中的 `workspace_id` 与工作目录字段为空；不是将用户主目录、系统根目录或某个隐藏项目当作默认目录。打开 Bot 不会创建项目，切换项目也不会改变它的执行环境。

读取文件时给出绝对路径，执行命令时明确指定该次命令的工作目录。缺少路径基准的相对路径操作会要求补充目标，不会落到上一次打开的项目或服务进程的目录。权限审批继续使用原生卡片。附件和其他会话资产保存在实例管理的存储中，与执行工作目录分离。

文件、搜索、补丁、终端与 LSP 工具都接受可选的 `folder` 参数，作为本次调用中相对路径的基准目录。全局（Bot）会话在给出绝对路径的 `folder` 后，可以直接使用相对路径，不必为每个参数重复前缀；`shell` 家族既接受 `workdir` 也接受 `folder`。普通项目会话始终以自己的项目根目录为基准，会忽略 `folder`，因此这些参数不会让项目会话越出项目。未提供 `folder` 时，Bot 仍需显式绝对路径，行为与之前一致。

涉及具体项目时，Bot 先查找目标项目，再在该项目的普通会话中交办、查看或继续工作；该目标会话使用自己的项目目录、模型与权限。Bot 自己仍保持全局身份。

## 会话与项目设置

会话层就设置在原有设置页中，而不是另开页面。模型配置、权限的文件与网络和工具页、提示词层都在作用域选择器里提供「当前会话」：选中后页面直接指向这台客户端最近使用的会话，并在顶部说明目标会话，不再提供会话选择器，也不使用 `?sessionId=` 参数。最近使用的会话在任意窗格或 Bot 绑定打开会话时记录。权限与提示词写入该会话自身；模型配置的会话层写入会话的持久选择（`/api/v1/sessions/{id}/selection`），只影响该会话后续运行。

项目层使用同一套页面的「工作空间」作用域，写入当前项目的 `.agena/agena.json`。Web 项目行的操作菜单提供「项目设置」，直达权限页的工作空间作用域，不再另有独立的设置分区或 `/session_setting` 命令。

## 直接交办

```text
列出我的项目，看看 agena 最近有哪些会话。

在 agena 项目里新建会话，检查测试失败原因，并补充验证。

继续刚才那个排查会话，让它补一下取消请求的测试。

看看该会话现在进行到哪里了，有哪些 Subagent 在工作。

把这个会话改名为「取消处理与回归测试」。

停止这个会话当前的执行。
```

Bot 会查询真实项目和会话，选择已有会话或在目标项目中新建普通会话，并返回可打开的会话链接。指令通过现有执行队列进入目标会话；该会话使用自己的模型、权限、工具和 Subagent。你可以直接从项目列表打开它、查看完整过程并继续输入，不需要进行“接管”或“交还”操作。

Bot 通过 `bot.sessions` 操作普通项目会话。项目聊天直接执行工作，按需要调用现有 Subagent；Bot 和用户共享同一份项目会话记录。

## 工具操作

| `bot.sessions` 操作 | 用途 |
|---|---|
| `projects` / `project` / `register_project` | 按名称或路径查找项目、查看详情、登记已有目录（不创建文件夹） |
| `sessions` / `create` | 跨项目或按项目查找会话，按标题、收藏、置顶、状态筛选；新建普通会话 |
| `read` / `read_text` / `status` | 分页读取记录和长文本，查看版本、队列、待处理决定与子 Agent |
| `send` | 向现有项目会话发送或追加指令 |
| `rename` / `organize` | 使用已观察到的版本改名、明确设置收藏或置顶 |
| `fork` | 在同一项目内分叉普通会话，继承指定边界的记录、模型与权限 |
| `models` / `configure` | 查看实际可用模型，用版本保护修改模型或运行选项 |
| `queue` / `queue_pause` / `queue_edit` / `queue_remove` | 查看队列，明确暂停或恢复、修改排队文字（保留附件）、移除指定排队项 |
| `delete` | 在 Bot 原生确认卡片中确认后，软删除一个空闲会话 |
| `export` | 返回需要正常登录的原生 JSONL 会话下载链接 |
| `stop` | 停止已观察到的当前执行 |

跨项目管理工具只允许服务端确认的操作者 Bot 调用。写操作关联当前用户消息和稳定的请求标识；重试不会重复创建会话或重复提交同一指令。改名和停止针对已读取的版本或执行代次，避免覆盖较新的人工操作。权限申请保留原生审批卡片；需要决定时可直接打开对应项目会话处理。

Bot 会自己将项目名、路径和会话标题解析为真实目标；有多个匹配时会澄清，不要求你查询内部 ID。它会优先继续相关的已有会话，并提供目标链接。已排队、正在执行、等待人工决定与执行结束是不同状态；Bot 需要查看实际记录和结果才能声称任务完成。

删除只影响一个会话的可见记录，不删除项目文件或目录。确认卡片会显示项目路径与 ID、会话标题和 ID。确认期间若有人修改目标、追加消息或产生新工作，操作会拒绝过期确认；Bot 中出现新的人类消息也会使旧确认失效。对“删掉这个项目”这类范围不清的要求，需要先明确是会话还是实际文件。普通分支在源会话软删除后仍可继续使用；被删除的频道或 Subagent 祖先仍保留隔离约束。分叉与队列操作使用稳定请求标识，丢失回执后的重试不会重复创建分支或重复排队。版本冲突不会自动覆盖人工的新操作。如果要求暂停整个会话的工作，Bot 会先暂停原生队列，再停止已观察到的当前执行；排队内容会保留，除非你明确要求移除。恢复时继续同一个队列，不重复交办。

## 实现与验证

默认入口使用 `POST /api/v1/bot/session`，返回 `{ "session_id": 123, "bot_id": "UUID", "name": "Agena" }`。`/api/v1/bots` 提供列表和创建；`/api/v1/bots/{id}` 提供精确读取和带版本保护的修改，`/{id}/session` 绑定指定 Bot，`/{id}/archive` 归档。身份、修订号、创建意图和幂等操作回执保存在现有实例 JSON 状态存储，原生创建回执保证崩溃重试不重复创建，执行仍使用 Session Kernel。

主要实现：

- `crates/agena-runtime-session/src/session/manager/bot.rs`：Bot 身份、授权、项目会话操作。
- `crates/agena-bundled-plugins/src/plugins/provided/bot.rs`：模型工具与 Bot 上下文。
- `packages/agena-web/src/pages/chat/useBotConversation.ts`：Web 会话绑定与切换保护。
- `crates/agena-tui-app/src/app_bot.rs`：TUI 入口、加载、重试与会话跳转。

```sh
cargo test -p agena --test system scenarios::bot --offline --locked -- --test-threads=1
cargo test -p agena --test system bot_web_and_terminal_share_normal_conversation \
  --offline --locked -- --ignored --test-threads=1 --nocapture
cd packages/agena-web
bun test ./tests
bun run build
bun run test:bot:browser
```

真实界面测试使用独立 Agena 实例、本地脚本化模型、Chrome 与私有 tmux，覆盖两端共享对话、实际发送目标和桌面/窄屏布局。
