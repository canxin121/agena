# 用自然聊天持续完成工作

人格、长期记忆和主动提醒已与这条工作链共用同一运行时，见 [完整助手使用说明](assistant.md)。

现在的主要入口是 **原来的 Web/TUI 聊天框**。Task 是后台保存工作身份、状态、执行关系和恢复信息的记录，不再要求用户手动建立、调度或维护。

## 直接这样说

```text
你：检查一下最近测试为什么失败，能修就修，并说明验证结果。
助手：开始检查，结果会回到这里。

你：顺便解释一下这个模块为什么这样设计？
助手：回答设计问题，后台工作继续。

助手：检查完成，下面是实际改动和验证证据……
你：再补一下取消请求的测试。
助手：原来的执行会话继续补测，完成后回到这里汇报。

你：先停下刚才的检查。
助手：停止对应工作及其委派的执行，不需要你找任务编号。
```

不需要 `/task`，不需要切换 Worker，不需要把任务 ID 复制回来，也不需要不断打开任务面板查询。`/tasks` 和原有任务页面保留为检查记录、人工介入和调试入口。

## 系统会做什么

普通聊天、短问题和轻量查询仍直接回答。对于明确交办的多步骤工作，前台助手使用默认启用的 `agena.work` 能力建立后台执行，并结束当前前台回合；执行由长期在线的 Agena 服务持有，不由浏览器页面或 TUI 进程持有。

每次模型请求都能看到当前对话的有限工作记录、状态、待回答问题和工具契约。助手据此把“刚才那个”“再补一下”“先停下”等后续要求关联到原工作。存在实质歧义时仍应澄清，不能随便选择另一项工作。

工作正在执行时，补充要求会可靠排队，在当前成功步骤结束后进入同一 Worker 的下一次执行；它不会伪装成已经抢占了正在运行的 Shell 命令。完成后的补充要求也继续使用原工作身份与 Worker 上下文，而不是再建一份重复任务。

用户关闭页面或终端不会因此删除工作。重新打开原会话可以看到已保存的回报；服务本身必须继续运行，或在停止后重新启动并恢复。这里的主动回报指回到 Agena 会话，不是 QQ、飞书或手机系统推送的新接入。

## 提问和权限就在原聊天处理

后台执行遇到问题时，问题会投影到原会话的现有交互卡片中，同时助手可以用自然语言说明需要你决定什么。

普通问题可以直接回答，例如“用 stable 分支继续”，由助手转交给确切的待回答问题。它只允许提交真实用户给出的有效答案。

**权限申请和操作审批必须由你通过原会话中的原生卡片确认。** 模型不能使用“回答问题”接口替你批准权限，也不能把自动报告当成新的授权。卡片仍指向真实的 Worker 和请求身份，不会为了方便展示而改写请求的所有者。

默认后台工作在执行回合成功结束后自动完成并汇报，不再要求额外点“验收”。这表示该执行回合结束，不是系统独立证明所有结果都正确；回报必须说明实际证据及未完成事项，不能编造测试通过。

用户明确说“完成后先给我看，等我确认”时，结果保留为待验收。之后直接说“最新结果没问题，确认完成”即可，不必打开 Task 页面。确认绑定结果版本；结果在确认之后才更新的，必须重新呈现并要求新确认，不能自动改版本重试。

## 可靠性和授权边界

### 不重复开工

创建工作绑定实际来源会话和真实用户消息身份。同一条用户消息只建立一个顶层工作，多个目标由这个工作在内部拆分。重复工具调用、回执丢失、重试改写措辞，都不能悄悄建立另一份工作。

后续操作有消息顺序和意图校验。旧回合不能覆盖新要求；同一用户回合对同一工作的不同写操作不会被当成普通网络重试。所有持久任务修改仍通过版本检查。

### 不丢失回报

任务状态和需要回报的事件在同一个 SQLite 事务中提交。回报正文先固定，再投递到原聊天的持久消息队列；忙时等待安全边界，空闲时按目标会话即时唤醒。

任务控制器读取当前通知消费状态，不把首次命令回执误当成当前状态，也不会在每次忙时轮询时增加一份新的命令记录。出错按通知独立退避，其他任务的回报不因此永久停止。

已经进入下一次执行的旧完成通知、已经解决的问题通知，会按当前工作状态识别为过期，避免把用户带回旧状态。

### 重启不是从头再做

结果已经产生但尚未送达时，恢复后补发该结果，不重做 Worker。正在运行而被中断的工作保持可检查的中断状态；未知外部副作用不会被无条件重放。用户可以在原聊天中给出恢复要求，助手使用原 Worker 核对既有结果后继续。

### 自动报告不是新用户

空闲会话被工作结果唤醒时，内核建立独立的控制续接执行，而不是重试旧用户输入。`work.manage` 的写操作要求来自真实当前用户消息的引文；自动结果、工具输出和旧用户消息不能经这个入口递归创建新工作。

引文校验证明的是输入来源与当前回合，不是完整的自然语言授权证明。是否属于交办、范围是否有歧义仍由模型判断和提示策略约束；执行中的真实工具权限、路径、网络和能力限制继续由现有运行时执行。

Worker 自身以及其 Subagent 被禁止建立顶层会话工作。短期内部委派仍使用已有 Subagent 能力，不取消其现有角色和预算限制。

## 实现位置

| 层次 | 文件 |
|---|---|
| 默认对话策略 | `crates/agena-bundled-plugins/assets/prompts/conversation-work.md` |
| 模型工具与上下文 Hook | `crates/agena-bundled-plugins/src/plugins/provided/work.rs` |
| Host 工具契约 | `crates/agena-plugin-sdk/src/host_api/work.rs` |
| 对话调度、关联、回报 | `crates/agena-runtime/src/runtime/superagent/conversation.rs` |
| 持久工作元数据 | `crates/agena-superagent/src/conversation.rs` |
| 原子状态与通知队列 | `crates/agena-storage-sqlite/src/superagent_repository.rs` |
| 真实用户来源、问题回答、即时唤醒 | `crates/agena-runtime-session/src/session/manager/managed.rs` |
| 原会话待办投影 | `manager/queries.rs` 和 `agena-api/src/resource.rs` |

`work.manage` 支持 `start`、`status`、`update`、`cancel`、`respond`、`accept`。工具不接收任意来源会话或用户身份；这些由运行时调用上下文提供。协议通过内嵌插件、HTTP/stdio Host 回调使用同一实现。

新增数据库结构采用完整旧基线匹配后的追加迁移；不把任意部分安装状态当作可修复的旧版本。更新真实实例前仍应备份。新版本写入后不承诺旧二进制可直接降级打开。

## 验证方法

```sh
# 普通聊天入口，不调用 Task 创建/控制接口
cargo test -p agena --test system scenarios::conversation_work --offline --locked \
  -- --test-threads=1 --nocapture

# 原子通知、去重、已有 Task 数据库迁移
cargo test -p agena-storage-sqlite --test superagent_tasks --offline --locked

# 真实 Chrome/Vue 和真实 TUI/tmux；全程不打开 Task 面板
cargo test -p agena --test system natural_conversation_workflow_without_task_controls \
  --offline --locked -- --ignored --test-threads=1 --nocapture
```

真实界面测试使用正常聊天输入，并审计浏览器不能偷偷调用 Task 写接口。后台交办、结果回报和同一 Worker 续办都通过真实产品进程、SQLite、权限、模型协议和通知链路完成。

测试模型是本地脚本化服务，用于稳定验证模型作出对应决定后的系统行为，不代表已经完成所有真实模型的语义判断评测。本轮不调用外部付费模型，也不据此保证不同模型都会同样可靠地判断复杂意图。

## 当前范围

这是单实例、单操作者的对话工作系统，顶层 Task 仍按保守串行策略执行；前台聊天不需要等待后台任务。已有 worktree、工具沙箱、权限系统各自的边界没有因为增加对话路由而自动扩大。

没有借此接入外部 QQ/飞书/GitHub 账号，也没有默认扫描你的消息自行创造新目标。跨渠道身份、自动发现工作、独立强隔离和更完整的长期语义监督属于另外的能力，不能把本轮普通聊天闭环的通过等同于它们已经实现。

## 外部渠道与事件驱动扩展

`agena.integration` v1 让聊天渠道和事件源通过插件扩展。已授权的外部事件可以直接创建本页的持久工作；结果仍进入原会话，并可通过渠道插件发送。规则只需由操作者明确启用一次，不要求每次 Issue 到来时创建 Task。`work.connections` 支持自然语言提出规则草稿、查看和暂停；完整安装、协议、授权和验收见 `docs/integrations.md`。
