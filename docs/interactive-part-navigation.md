# 可操作 Part：Web 与 TUI 的统一交互

这次改造保留消息流里的 Vim 光标，把操作控件纳入同一条浏览路径。光标所在的位置决定 Enter 的含义；上下移动光标不改变答案；问答控件上的左右键切换题目，空格选择答案，Enter 确认并继续或提交。

## 可操作区域清单

| Part / 区域 | 可以执行的操作 | 进入方式 |
| --- | --- | --- |
| Operation 中的 Plan review | 批准并开启 autorun、批准但关闭 autorun、继续规划、拒绝、取消整个计划；输入修改意见 | 展开 operation，再移动到具体决定按钮 |
| Operation 中的 Ask user | 单选、多选、自定义回答、上一题、下一题、答案汇总、修改某题、提交、稍后处理 | 展开 operation，正文和选项沿同一光标路径浏览 |
| Operation 中的权限请求 | 允许一次、持久允许、拒绝；TUI 另有完整权限详情、作用范围和规则入口 | 请求随 operation 内联显示，按标题 Enter 可以收起 |
| Operation 的技术详情 | 展开输入、输出、元数据、呈现数据；Web 的加载、失败重试 | 定位对应的小标题或按钮，再按 Enter |
| Operation 的终端 / 日志 | 终端输入、选择、滚动、复制、跟随最新输出；日志刷新 | 有独立的紧凑工具栏；进入终端或日志滚动区后保留自己的按键 |
| 代码 / Diff | 复制完整内容、展开 / 收起长内容 | 复制与展开始终有可见边界，滚动区保留原生按键 |
| Resource / 附件 / 搜索结果 / 引用 | 客户端已有的预览、打开、复制等入口 | 文件与链接使用有图标的操作行；没有地址的资源保持静态文字 |
| Command、reasoning、answer、notice、compaction、error 等详情 | 标题上的展开 / 收起；内容自带的链接、复制等按钮 | 标题和实际控件各自拥有 Enter，普通正文不触发外层折叠 |
| Plan 状态查看器 | 展开计划、刷新、设置 autorun | 保留会话配件入口；审核决定属于 operation 的 Plan review |

Part 的类型本身不代表它会提交决策。能执行的动作必须对应一个实际控件；已完成请求显示结果，不再提供可提交的旧动作。

## 光标与按键

| 光标位置 | H / 左 | L / 右 | J / 下、K / 上 | Enter | Esc |
| --- | --- | --- | --- | --- | --- |
| 普通正文 | 按字素移动，中文和 emoji 不拆分 | 按字素移动 | 按可见行移动；遇到控件落到整个控件 | 无可执行对象时不动作 | 保留消息浏览的原有规则 |
| Part 标题 / 技术详情小标题 | 按对应客户端的标题光标浏览 | 按对应客户端的标题光标浏览 | 可以进入展开内容或离开 part | 切换该标题的展开状态 | 不代替 Enter 收起 |
| 审核 / 权限 / 其他操作按钮 | 前一操作；同排时按空间位置移动 | 后一操作；同排时按空间位置移动 | 下一 / 上一可见对象，长选项整块只算一次 | 执行当前操作 | 交互区返回 part 标题，保留展开和草稿 |
| 问答选项 / 导航按钮 | 上一题；第一题停留 | 下一题；最后一题停留 | 下一 / 上一可见选项，长选项整块只算一次 | 确认已有答案，进入下一题；最后一题提交 | 返回标题，保留答案 |
| 自定义输入框 | 编辑器移动光标 | 编辑器移动光标 | 编辑器移动光标，HJKL 作为文字输入 | 确认当前回答；审核反馈提交；空输入退出编辑 | 退出当前编辑层，保留草稿 |
| 已完成的历史结果 | 正常文字浏览 | 正常文字浏览 | 正常文字浏览 | 不重复提交旧请求 | 正常返回 |

- 控件列表不循环到开头。上、下可以继续进入前后的正文和 part，不把用户锁在审核区。
- Web 保留 Tab / Shift+Tab 的原生焦点顺序；未开启 Vim 时也可正常操作。
- 问答控件上的 H / L 切换上一题 / 下一题，不自动选择或提交；审核和权限控件继续按实际按钮移动。
- 数字前缀继续作用于移动；视觉选择保留文字的行、字素与范围语义。
- 终端、代码滚动区、下拉选择器和文本编辑器保留已有的按键所有权。输入法候选确认不会变成操作提交。
- 鼠标点击问答选项只选择 / 切换该选项，其他按钮执行对应动作。Web 的完整选项行（含标签与说明）属于控件区域，轻微拖动不进入正文文字选择，也不会双重切换；题干、普通正文和已完成答案仍支持文字选择。TUI 只把控件实际列范围内的单击作为操作，缩进和空白不触发。

## Plan review

计划正文先以标准 Markdown 呈现，随后平铺“决定”标题和按钮列表，不再包裹额外卡片。Web 每个待处理选项固定为一行，常态显示边框和底色，图标、加粗标题、次级说明形成明确层次；标题与说明之间用竖线分开。长文本省略，原文保留在无障碍描述和悬停提示中；聚焦整个操作行，Enter 直接执行该决定。TUI 按终端宽度换行显示说明。

当请求进入 active 阶段时，标准决定为：

1. **Approve with autorun on**：批准并开启 autorun。
2. **Approve with autorun off**：批准并关闭 autorun。
3. **Keep in planning**：继续规划。
4. **Reject**：拒绝当前审核。
5. **Cancel plan**：取消整个计划。

其他目标阶段沿用服务端提供的对应批准选项；客户端不推测或改写决策协议。

“提交反馈”是独立的编辑入口，打开输入框后可以填写修改意见。界面不要求先选择一个普通决定再寻找第二个确认按钮。移动焦点不会预选“批准”。

“稍后处理”沿用当前请求的取消回复语义，和 **Cancel plan** 是两个不同的显式动作：前者取消这次审核并回到规划，后者把整个计划设为 cancelled。收起标题和 Esc 都不发送取消回复。

Web 与 TUI 的已完成审核只显示实际提交的决定及说明，或完整的反馈文字，不再保留其他禁用选项、操作箭头和旧输入框。取消、超时和没有回复的历史请求分别显示对应状态；未提交的草稿始终与这些结果分开。

## 问题与汇总

- 一页一个问题，保留完整题干。Web 选项标题和说明使用紧凑行，完整原文仍可通过悬停提示和无障碍名称读取；多选和单选用不同标记。
- 上 / 下、J / K 移动选项焦点；空格选择单选答案或切换多选答案，光标留在原处。重复空格保持单选选中，多选可以再次取消。焦点和已选状态分别显示。
- 左 / 右、H / L 切换上一题 / 下一题，可以先浏览未回答的问题，切题保留所有已填答案。到第一题或最后一题时不循环、不自动提交，也不进入汇总。
- Enter 确认当前题已有的答案；即使光标在另一个未选择的选项上，也不替换单选答案、不切换多选答案。没有回答时停留并提示；有回答时进入下一题，最后一题直接提交整个请求。
- Web 汇总以紧凑行展示每题及回答摘要，悬停可读完整回答，Enter 返回该题编辑；TUI 按终端宽度完整换行，问答页脚的各个动作独占一行，均可用上下键到达。
- 最后一题提供“发送答案”和可选的“查看汇总”。汇总中的 Enter 返回该题编辑，也可通过“发送答案”提交。任何提交路径都校验全部问题；缺少答案时回到第一道漏答题，保留其他答案，重复提交受请求处理中状态保护。
- 自定义回答是选项类型：工具在 `options` 中提供 `{ "label": "自定义回答", "custom": true }`。它可以是整题唯一的选项，无需附带固定选项；也可以与普通选项混排。选项标题和说明由题目提供，旧请求的 `allow_custom` 开关继续兼容。
- 自定义项与普通选项使用相同的单选 / 多选标记、点击区域和焦点样式。空格或鼠标选择后打开同行下方的输入框；单选时与固定项互斥，多选时可组合或取消。取消选择、切换固定选项及关闭编辑都保留文字草稿，提交只包含当前选中项的实际值。选中自定义项却没有填写内容时不能继续；不会将“自定义回答”这一选项标题当作答案发送。
- 自定义回答支持中文和长文本。逗号和换行保留在同一个自定义答案内。输入框内的方向键仍移动文字光标，HJKL 与空格仍输入文字；Enter 确认当前回答，最后一题直接提交。Web 的 Shift+Enter 换行；选区、剪贴板和输入法保持编辑器语义。

## 权限与请求生命周期

权限请求在 TUI 内联显示动作、申请原因和明确按钮，常见处理不再自动打断为弹窗。选择持久允许时进入既有的作用范围选择，避免隐藏地决定保存范围。详细权限页保留原有的规则编辑和自动审批功能；其中方向键 / HJKL 只移动或滚动，Enter 才激活。

Web 保留已有的允许一次、始终允许、拒绝三个 API 动作。两个客户端都核对请求身份和待处理状态。过期请求不重复回复，请求处理中阻止重复提交；失败保留回答并恢复可操作状态。另一个客户端解决请求后，Web 将焦点返回存活的标题并显示结果。

## 其他交互 Part 的统一外观

- 整体沿用普通 Part 的内容轨道。交互标题与状态在同一行自然排列，不加外层边框、圆角面板或底色；层级由标题、字重和留白表达。
- 已完成的提问和审核使用题目、答案列表和普通反馈段落平铺，不给每道题再套一张结果卡片。保留完整答案、说明和换行。
- 权限请求将申请的动作、原因、来源和最终回复作为普通段落显示，只有三个实际决定保留图标与按钮边界。拒绝使用警示色，提交时禁用全部决定并在当前动作上显示进度。
- 技术详情的主入口与输入、输出、元数据、呈现数据使用小箭头加文字的轻量展开行。子项仅缩进，不添加第二条侧边框或全宽按钮框。加载、错误和重试留在对应子区域，原有两级折叠和按需读取保持不变。
- 代码、Markdown 代码、Mermaid、Diff、实时输出和活动日志共用紧凑按钮与透明工具栏。复制入口始终可见；展开、跟随、刷新等实际动作仍有图标和明确按钮。输出与日志不再附加外层卡片，代码块本身保留与普通 Markdown 一致的阅读样式，原生滚动不变。
- 附件、搜索结果和引用使用图标、带下划线的链接文字及次级信息，不把资源行画成卡片。本地文件仍打开工作区，远程文件仍使用原生链接；没有地址的内容保持静态。图片保留原来的预览尺寸上限，视频、音频保留原生播放器。Plan 查看器的 autorun 使用普通原生勾选行。

## 外观与实现约束

- Web 的实际操作按钮和待处理选项保持桌面 32px、触屏 36px（随根字号缩放），选项间距 6px。只有这些控件保留常态边框和底色，外层正文与完成态结果不加框。操作区最大宽度 48rem（默认字号下 768px），窄窗格自动收缩。标题加粗，说明降为次级文字并以竖线分隔；长段落、换行和长单词都不会撑高按钮。14px 图标置于 20px 图标位，不再给图标叠加小底色框。批准、修改、拒绝、取消各有对应符号，不自动选中任何决定。反馈入口用按内容宽度的虚线按钮区分。
- 已完成请求改为无交互的结果区，完整保留已提交内容和换行；问题历史只列实际回答及题干，不再重复整组选项。取消和未回答状态也不显示旧操作或草稿。
- **光标焦点**用清晰的轮廓表达；**已选答案**用选中标记、边框和浅底色表达。聚焦某个选项不会把它画成已经回答。
- TUI 的选项、答案汇总和权限动作沿正文缩进平铺，以单选 / 多选标记、动作符号和文字颜色识别操作，不叠加面板侧边框或常态底色。聚焦时高亮实际控件范围，长选项的所有换行属于同一个落点；普通题干和计划正文仍显示文字光标。操作栏按整个按钮换行，不在半个按钮处分割，复制文本和指针的有效列范围保持稳定。
- TUI 的每个控件携带 request id、动作类型、列范围和启用状态。键盘、指针和焦点绘制使用同一份渲染元数据，删除旧的“第几行代表哪个选项”的固定偏移计算。
- TUI 用动作身份保存光标锚点，终端缩放和内容换行后仍停在原动作。长计划首次显示保持标题和光标可见，随后按正常消息浏览阅读。
- Web 按可见控件矩形和文字行计算相邻落点，跳过隐藏、禁用和 inert 控件，保持窗格焦点范围。技术详情继续按需加载。

## 验证

Web 的回归覆盖左右切题及边界、空格选择、Enter 保留现有答案并直接提交、漏答回跳、自定义输入按键所有权、空间方向选择、按钮换行、离开操作区、文档边界、单选 / 多选提交、审核直接提交、重复提交保护、失败保留答案，以及已完成决定、反馈、多选历史、取消与未回答状态只展示已提交结果。组件回归还检查权限处理中统一禁用、历史回复的多行原因、附件的本地按钮 / 远程链接、无地址资源的静态状态与技术详情按需读取。浏览器夹具另检查标签与说明上的轻微拖动准确选择一次，并检查待处理选项的高度、边框和底色，以及外层上下文、完成态结果、技术详情和资源链接保持无框无底色；同时检查行间距、最大宽度、窄屏溢出及附件 Enter 动作。TUI 覆盖标题和正文 Enter、Esc 返回标题、自由进入 / 离开、长中文和 emoji 说明、缩放保持动作、权限内联和作用范围、指针空白边界、完成态仅保留已提交内容，以及平铺控件的复制与动作元数据。

本次环境没有可连接的浏览器实例，未完成真实浏览器截图和视觉验收。现有浏览器夹具位于 `packages/agena-web/tests/fixtures/interaction-keyboard.html`，可用于继续检查浅色 / 深色、窄屏、焦点轮廓和 IME。
