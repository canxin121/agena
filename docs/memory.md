# Agena 分层记忆

Agena 将当前任务、历史经历和长期知识分别管理。原始会话与工具事件继续保存在 session kernel 中；Markdown 记忆是便于读取、检索和编辑的知识视图，每条记录可以关联宿主提供的来源身份。

## 日常使用

- 继续当前工作时，优先读取当前 session 的任务检查点，并用最近对话补全“继续”“上次那个方案”等短请求。
- 查询历史决定或类似任务时，使用 `memory.search`；结果包含相关正文片段、正文行号、来源、状态和 `memory.get` 读取参数。
- 保存明确偏好、项目决定或有效方法时，使用 `memory.write`。
- 纠正同一条记录时，先 `memory.get`，再使用当前 `sha256` 更新。
- 新记录替代旧记录时，在写入中提供 `supersedes` 和各旧记录的当前版本。
- `memory.list` 是有分页的导航列表；`memory.get` 按 Unicode 字符分页返回正文、完整记录的 SHA 和元数据，默认每页 8000 字符，最多 32000 字符。使用 `body_range.next_offset` 继续读取，跨页核对 SHA，防止拼接两个不同版本。
- 默认搜索和自动召回只使用当前有效、作用域匹配的记录；搜索或列表传 `include_history: true` 可查看已归档和被替代的历史。因来源遗忘而抑制的派生记录在历史查询和直接读取中也保持隐藏。

类型和作用域各有独立职责。`kind` 表示事实、偏好、经历、方法或当前任务；`scope` 决定记录适用于整个工作区还是当前 session。原有 `memory_type` 标签继续兼容，`user` 标签本身不会扩大工作区权限或成为全局用户记忆。

### 保存与纠正

保存项目决定：

```json
{
  "name": "database-choice",
  "description": "数据库选型及决定原因",
  "memory_type": "project",
  "kind": "fact",
  "scope": "workspace",
  "content": "采用 PostgreSQL；原因和已验证条件记录在这里。",
  "importance": 70
}
```

更新同名记录时，将 `memory.get` 返回的 `sha256` 填入写入参数 `expected_sha256`。管理界面的编辑、单项删除和批量删除也携带版本；出现冲突时保留编辑草稿，重新加载现状后再提交。若用一条新记录替代另一条：

```json
{
  "name": "database-choice-current",
  "description": "当前数据库选型",
  "memory_type": "project",
  "content": "当前决定及其依据。",
  "supersedes": [
    {"name": "database-choice", "sha256": "<读取旧记录所得的版本>"}
  ]
}
```

一次替代会原子更新新记录、旧记录状态、导航索引和元数据。旧正文保留用于解释历史，默认召回排除旧记录。版本不匹配时整次写入失败，调用者应重新读取现状。

当前任务笔记使用 `kind: "task"`、`scope: "session"`；session ID 和存储实例 ID 由宿主填入。数据库重建后重复出现相同的整数 session ID，也不会匹配另一实例的任务笔记。自动生成的 Task 还必须对应 kernel 当前已提交的检查点；旧投影在后台更新前不进入默认召回，必要时可按历史记录查看。

## 自动召回

召回过程按以下顺序执行：

1. 提取用户消息中的可见文本。图像、附件、工具数据和推理内容不会被拼成检索词，原始消息结构保持不变。
2. 对短请求或续接请求，加入有界的近期用户与助手文本；明确的新问题保持独立查询。
3. 检查记忆开关、工作区权限、记录权限、实例和 session 作用域。
4. 使用有界的字面查询进行全文检索。中文使用独立的 CJK n-gram 条件；路径、错误码和代码标识符保留精确匹配信号。
5. 优先选择当前任务与重要偏好；其余记录按查询匹配选择。
6. 从命中的正文位置选择片段，并在上下文预算缩小时重新选择更小的匹配窗口。
7. 将少量核心信息和相关证据装配成模型上下文。

`min_query_chars` 用作补充历史上下文的阈值；短而明确的“数据库”等查询仍会搜索。用户在当前请求中明确要求不用记忆时，会跳过自动召回。

核心偏好依据重要度和更新时间排序，并受预算约束。查询命中保留独立预算；命中的偏好如果未装入常驻区，仍可进入相关证据区。只有实际装入上下文的内容才去重，避免零常驻预算或偏好增多时漏掉当前问题的证据。预算采用跨模型的保守 token 估算，同时有 UTF-8 字节上限。

搜索输出有 `trace`，包含作用域过滤后的记录数及历史过滤信息；命中项包含分数、匹配词、正文片段和读取入口。自动召回在 `agena::memory` tracing target 下记录是否补充历史、索引记录数、过滤数量及注入规模，便于定位失败发生在哪一层。

索引是可重建缓存。每次检索重新检查源记录和当前授权范围；同一快照中只更新变化的文档，未变化的文档不重复提交。返回前再次将候选与本次授权源快照对照，避免共享缓存中的其他 scope 内容进入响应。

## 后台经历与任务检查点

正常执行结束或会话压缩提交后，运行时按 session 合并维护请求，等会话空闲且没有运行或排队中的执行，再整理经历。抽取复用已配置的辅助模型；没有单独配置辅助模型时沿用会话的模型选择。整理工作在后台进行。

经历抽取遵循以下规则：

- 至少达到 `min_user_messages`，并且有实际完成的工具结果，或累计至少三条用户消息。默认值为 1，因此单次请求完成的代码任务也能形成经历，简单问候不会触发抽取。
- 保留有用的决定、约束、已观察结果、后续事项和经验，并引用真实 kernel entry。实际结果必须引用工具证据；助手自行声称完成不能作为验证。
- 输入包括有界的近期事件、初始任务目标，以及旧摘要所引用且仍可读取的较早来源。证据最多 48 条、正文合计最多 32 KiB，另带最多 12 KiB 的旧摘要。
- `memory.*` 的读写结果、工具发现输出、推理和注入通知不作为独立事实来源。读取真实 `tools_call` 包装内的执行工具身份；来源窗口包含成功的 `memory.delete` 时跳过经历抽取。
- 子 agent、旁路对话，以及携带其他会话历史前缀的 fork/rewind 跳过自动整理。检查历史前缀的原始 session，不依赖近期窗口；有独立历史的 Child 或空 rewind 仍可整理自己的执行结果。

任务检查点直接复制已提交 compaction 的可读摘要，最多 64 KiB，并保留来源 checkpoint 与覆盖位置。这一步不再调用模型。provider 的加密 replay 保留在 kernel 的 provider metadata 中；没有可读摘要时跳过文件投影。任务文件绑定宿主实例及当前 session，kernel 继续决定真实执行状态。

### 调度、取消与保存

默认空闲等待 30 秒，同一经历两次成功更新之间冷却 300 秒。冷却期内出现的新结果会保留待办，到期后自动补跑，无需再收到一条用户消息。辅助调用名额暂时占满，或目标记录未变但其他记忆写入使存储 generation 失效时，最多延迟重试两次，每次间隔 5 秒；重试重新读取来源并抽取，不直接发布旧草稿。

经历抽取共用运行时的四个辅助调用名额，每次模型请求最多 30 秒，默认输出预算为 1536 tokens。关停会取消空闲/冷却等待和进行中的辅助模型请求，已经进入的文件提交纳入运行时的任务排空流程。等待中的 timer 保存在进程内，关停后不保留；已保存的记录、来源进度和删除抑制持久化。重启不批量扫描全部历史，下次会话事件会重新调度并依据 kernel 历史继续整理。

后台写入要求记忆插件和维护开关启用、用户记忆开关允许、`memory.write` 工具策略及相关路径明确为 `Allow`。这包括正文、索引、元数据、journal 和 lock；`Ask`、`Auto`、`Deny` 都会跳过后台写入。remembered rules 按会话所属工作区解析；私有频道使用自己的 memory root，并重新检查频道授权。

发布前重新检查当前配置、记忆开关、权限、来源条目版本、最新历史位置和删除抑制。存储锁、内容 CAS 与 generation 检查保护文件提交；显式写入、手工编辑和非活动记录不会被后台覆盖。SQLite 会话状态与文件投影之间采用写前复查。

删除标记阻止后台重新创建同名记录。对于有可信实例和 session 来源的删除，还会持久抑制该来源会话的派生记忆；同来源的已有派生记录不再参与召回，换名字、等待事件滑出近期窗口或重启都不会解除抑制。私有来源历史保留跨次编辑的归属，所以先通过界面编辑、清空当前归因再删除，原来源仍会受到抑制。外部修改已抑制摘要的字节也不会使它重新可见。显式记录保持独立，用户仍可明确写入新记忆。

## 来源、状态与持久化

旧 Markdown 文件可直接读取。新的宿主元数据保存在工作区记忆目录的 `.memory-state.json` 中，并与正文版本绑定：

- 稳定记录 ID、单调版本和创建/更新时间；
- kind、作用域、状态和重要度；
- 宿主实例、session、工具调用或 kernel 条目来源；
- 替代关系、写入来源和删除标记。

`provenance_verified` 表示当前文件字节与宿主记录的来源版本一致；事实是否成立仍需结合来源和当前环境判断。直接修改 Markdown 后，旧来源证明失效，内容作为外部编辑处理，并受到后台覆盖保护。

正文中的可选 `revision` 使元数据变更也会改变 SHA，因而旧编辑界面不能在不知道状态已变化时覆盖新版本。

写入使用进程锁、跨进程文件锁和可恢复事务，同时发布正文、导航索引及元数据。journal 保存事务开始前的版本；中断后恢复这些版本，再继续新的操作。正常读取不创建锁文件，也不要求写权限；发现未完成事务时，普通读取拒绝暴露中间状态。

`memory.get`、`memory.list`、`memory.search` 和自动召回保持只读，不触发源文件恢复。已获授权的 `memory.write`、`memory.delete`，或具有写工具权限的后台维护，可以显式进入恢复流程。后台维护先读取有界的待恢复目标清单，并逐个授权；工具写入使用保留宿主回调身份的路径过滤器，逐项检查真实目标。每个恢复目标都要求非交互的明确读写允许。存储层取得独占锁后重新读取 journal，重新核对实际目标；任何未经批准的新目标、符号链接或非法路径都会使恢复失败。拒绝恢复时保留 journal 和现有字节，等待有权限的操作处理。

## 配置

插件配置位于 `plugins.list."agena.memory".settings`：

```json
{
  "retrieval": {
    "enabled": true,
    "limit": 3,
    "min_query_chars": 8,
    "max_context_tokens": 2048,
    "core_context_tokens": 768
  },
  "maintenance": {
    "enabled": true,
    "idle_seconds": 30,
    "min_user_messages": 1,
    "cooldown_seconds": 300,
    "max_output_tokens": 1536
  }
}
```

`retrieval.enabled` 控制自动读取，`maintenance.enabled` 控制后台整理，两者独立。用户的工作区记忆总开关会停止自动读取和模型写入；已有条目仍可查看、删除，并可在管理界面纠正。会话无法读取宿主记忆策略时，自动召回跳过，模型写入报错。已授权的 operator 工具调用继续按宿主提供的工作区和逐路径权限管理记录；operator sentinel 不作为真实 session 或来源保存。

预算和时间参数有边界校验。后台请求还受运行时统一的辅助调用并发、超时和输入大小限制。源码测试中的模型提供器是本地可控 fixture；普通集成场景关闭后台维护，专门的生命周期测试验证其行为。

## 验证

针对本次实现的主要测试入口：

```bash
cargo test --offline -p agena-memory-index
cargo test --offline -p agena-storage --lib memory
cargo test --offline -p agena-application --lib memory_api
cargo test --offline -p agena-bundled-plugins --lib memory::
cargo test --offline -p agena-runtime-session --lib session::manager::memory::tests
cargo test --offline -p agena --test bundled_plugins memory -- --test-threads=2
cargo test --offline -p agena --test system scenarios::assistant -- --test-threads=2
```

回归用例覆盖中文自然问法、混合代码标识符、图文消息的文本投影、短请求续接、后部证据、上下文预算、四条以上偏好、零常驻预算下的相关偏好、任务检查点时效及作用域、分页正文、纠正和历史查询、旧版本冲突、手工编辑、忘记与后台写入竞争、关闭记忆、压缩检查点及进程重启。

后续调整检索策略时，应固定模型、工具权限和历史截止时间，对比关闭记忆、当前实现、直接检索历史和候选新方案；主要看实际任务成功率、用户纠正次数、重复失败步骤、错误/过期记忆注入率及延迟。
